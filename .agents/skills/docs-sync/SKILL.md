# Docs Sync (JARVIS / Kirieshka v2)

Процедура проверки и синхронизации документации репозитория с фактическим состоянием кода. Построена на динамическом авто-обнаружении файлов, роутов, событий и документов, поэтому остаётся актуальной при рефакторинге, добавлении новых модулей и изменении структуры кода.

## Границы и запреты

1. **Не трогать архивы:** каталог `docs/archive/` хранит исторические аудиты и планы — не редактируй его при синхронизации.
2. **Не менять код без запроса:** если задача касается только документации, правь только `.md` файлы (исключая `docs/archive/`).
3. **Только проверяемые факты:** не выдумывай имена файлов, эндпоинты, события, флаги, пороги и числа тестов. Всё вносимое в документ должно быть прочитано в текущем коде или получено из реального запуска.
4. **Соблюдать `AGENTS.md`:** активная ветка `osnova`, принцип **Zero-LLM Core**, фронтенд только **Tauri v2 + React (`ui/`)** (`ui_archive/` — архив, не возвращать PySide6 как текущий интерфейс), безопасность через `security/sandbox.py`, кладбище отброшенных фич (поканальный микшер, бэкап сейвов игр, автовосстановление VPN / сложные сетевые сторожи, фоновые алерты перегрева) не возвращать в актуальные документы.
5. **Никаких машинно-зависимых ссылок:** в документации репозитория используй относительные markdown-ссылки (например, `../ui/src/...` или `ARCHITECTURE.md`), а не локальные `file:///d:/...`.

## Пошаговый алгоритм

### Шаг 1. Автоматический пре-аудит и срез фактов (без LLM)

Сначала прогони встроенный скрипт аудита. Он сам обнаружит все кодовые директории и активные `.md` документы, проверит ссылки, версии, индекс `docs/INDEX.md`, покрытие `docs/COMPONENTS_MAP.md` и зашитые счётчики тестов:

```powershell
.venv\Scripts\python.exe .agents/skills/docs-sync/scripts/audit_docs.py --facts
```

Для машиночитаемого вывода добавь `--json`.

### Шаг 2. Выбор цели и сверка по ролям документов

Открой карту соответствия: [doc_code_map.md](./references/doc_code_map.md).

Определи, какие документы нужно проверить (точечно после конкретной правки кода или полный проход по всем активным документам).

### Шаг 3. Экономное чтение кода и сверка расхождений

В Windows-среде репозитория для поиска по коду используй `git grep -n` или `Select-String` (не полагайся на наличие `rg`), а файлы читай точечными диапазонами строк:

1. **Ссылки, пути и индекс:** исправь или удали битые относительные ссылки, замени `file:///` ссылки на относительные, зарегистрируй все неиндексированные `docs/*.md` в `docs/INDEX.md`.
2. **Версия и ветка:** проверь блок `Versions` из `audit_docs.py` — `core/version.py` (`APP_VERSION`), `ui/package.json`, `ui/src-tauri/tauri.conf.json` и `README.md` должны совпадать.
3. **Карта подсистем (`docs/COMPONENTS_MAP.md`) и структура (`docs/AI_GUIDE.md`):** добавь все файлы из `uncovered_in_components_map` (и убери удалённые/архивированные), сверь верхнеуровневое дерево каталогов в `AI_GUIDE.md` с реальным репозиторием.
4. **API и WebSocket (`docs/ARCHITECTURE.md`):** сверь список роутов и WS-событий из `--facts` с описанием в `ARCHITECTURE.md`, а при необходимости уточни детали в `services/gateway/routers/*.py`, `services/gateway_service.py` и `ui/src/services/`.
5. **Команды (`docs/COMMANDS.md`):** сверь триггеры, режимы обработки и категории с `services/command_catalog.py`, `services/command_router.py` и диспетчерами `services/router/*.py`.
6. **UI и статус (`docs/PROJECT_STATUS.md`, `README.md`, концепты):** сверь список экранов/вкладок (`ui_views` из `--facts`, `ui/src/App.jsx`, `ui/src/components/IslandApp.jsx`, `ui/src/motion/`), а отмеченные `[x]` / `[ ]` задачи — с реальным кодом.
7. **Тесты:** если в документе указано точное число тестов (подсвечено в `hardcoded_test_claims`), получи актуальное число через:
   ```powershell
   .venv\Scripts\python.exe -m pytest tests/ --collect-only -q
   ```
   Не переписывай числа «на глаз». Если нужен статус `passed`/`skipped`, прогоняй `.venv\Scripts\python.exe -m pytest tests/`.
8. **Входные доки для ИИ:** убедись, что `AGENTS.md`, `docs/INDEX.md`, `docs/GEMINI.md`, `docs/AI_GUIDE.md` и `.gemini/rules.md` не противоречат друг другу.

### Шаг 4. Точечная правка и валидация

1. Внеси минимальные точечные правки в расходящиеся `.md` документы, сохраняя язык (русский) и стиль исходного файла.
2. Повторно прогони скрипт валидации и убедись, что ключевые списки проблем пусты:
   ```powershell
   .venv\Scripts\python.exe .agents/skills/docs-sync/scripts/audit_docs.py
   ```
3. Если правились только `.md` файлы документации, запускать `pytest` для проверки кода не требуется (согласно `AGENTS.md`).
