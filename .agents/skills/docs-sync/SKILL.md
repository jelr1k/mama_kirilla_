# Docs Sync (JARVIS / Kirieshka v2)

Процедура проверки и приведения документации репозитория в соответствие с фактическим состоянием кода.

## Границы и запреты

1. **Не трогать архивы:** каталог `docs/archive/` хранит исторические документы, аудиты и планы — не редактируй его при синхронизации.
2. **Не менять код без запроса:** если задача касается только документации, правь только `.md` файлы (исключая `docs/archive/`).
3. **Только проверяемые факты:** не выдумывай имена файлов, эндпоинтов, флагов, настроек и количества тестов. Всё, что вносится в документ, должно быть прочитано в текущем коде или получено из реального запуска.
4. **Соблюдать `AGENTS.md`:** активная ветка `osnova`, принцип Zero-LLM Core, фронтенд только Tauri v2 + React (`ui/`), `ui_archive/` — легаси, отброшенные фичи (поканальный микшер, бэкап сейвов игр, сложные сетевые сторожи, фоновые алерты перегрева) не возвращать в актуальные доки.

## Пошаговый алгоритм

### Шаг 1. Автоматический пре-аудит (без LLM)

Сначала прогони встроенный скрипт аудита, чтобы быстро увидеть битые ссылки, несуществующие пути и непокрытые файлы кода:

```powershell
.venv\Scripts\python.exe .agents/skills/docs-sync/scripts/audit_docs.py
```

Для машиночитаемого вывода добавь `--json`.

### Шаг 2. Выбор цели и карты соответствия

Определи, какие документы проверяются (один конкретный файл или полный проход), и открой карту соответствия:
- [doc_code_map.md](./references/doc_code_map.md)

### Шаг 3. Экономное чтение кода и сверка

Не читай целые крупные файлы подряд — ищи нужные определения (`rg -n` по роутам, классам, командам, компонентам) и читай фрагментами:

1. **Ссылки и пути:** исправь или удали битые ссылки и устаревшие пути, найденные `audit_docs.py`.
2. **Версия и ветка:** сверь версию в `README.md` с `APP_VERSION` из `core/version.py` (и при необходимости `ui/package.json` / `ui/src-tauri/tauri.conf.json`).
3. **API и WebSocket (`ARCHITECTURE.md`):** сверь список REST-эндпоинтов с декораторами в `services/gateway/routers/*.py` и клиентскими вызовами в `ui/src/services/api.js`, а события WS — с `services/gateway/hub.py` и `ui/src/services/assistantSocket.js`.
4. **Команды (`COMMANDS.md`):** сверь триггеры, примеры и режим обработки (`Router` / подтверждение / `LLM`) с `services/command_catalog.py` и диспетчерами `services/router/*.py`.
5. **Карта подсистем (`COMPONENTS_MAP.md` и `AI_GUIDE.md`):** добавь новые модули из отчёта `audit_docs.py`, убери удалённые или перенесённые в `presentation/legacy/` / `ui_archive/`.
6. **UI и статус (`PROJECT_STATUS.md`, `README.md`):** проверь, что разделы/вкладки совпадают с `ui/src/App.jsx`, `ui/src/components/`, `ui/src/components/IslandApp.jsx`, а отмеченные `[x]` / `[ ]` задачи соответствуют реальному коду (не оставляй PySide6-компоненты вроде `start/splash.py` как текущий основной интерфейс, если они заменены).
7. **Тесты:** если в доке указано точное количество тестов (`PROJECT_STATUS.md`, `AI_GUIDE.md`), получи актуальное число через:
   ```powershell
   .venv\Scripts\pytest tests/ --collect-only -q
   ```
   Не переписывай число «на глаз». Если нужен статус `passed`/`skipped`, прогоняй `.venv\Scripts\pytest tests/` (или убирай устаревшее жёсткое число, если полный прогон не заказывался).
8. **Входные доки для ИИ:** убедись, что `AGENTS.md`, `docs/INDEX.md`, `docs/GEMINI.md`, `docs/AI_GUIDE.md` и `.gemini/rules.md` не противоречат друг другу и ссылаются на реально существующие файлы.

### Шаг 4. Точечная правка и валидация

1. Внеси минимальные точечные правки в расходящиеся документы, сохраняя язык (русский) и форматирование исходного файла.
2. Повторно прогони скрипт валидации, чтобы убедиться, что не осталось битых ссылок и новых пропусков:
   ```powershell
   .venv\Scripts\python.exe .agents/skills/docs-sync/scripts/audit_docs.py
   ```
3. Если правились только `.md` файлы документации, запускать `pytest` для проверки кода не требуется (согласно `AGENTS.md`).
