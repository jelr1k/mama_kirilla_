# Правила работы с JARVIS (Kirieshka v2)

Эти правила действуют для агентной работы в этом репозитории. Подробный контекст: [`docs/AI_GUIDE.md`](docs/AI_GUIDE.md) и [`docs/GEMINI.md`](docs/GEMINI.md).

## Перед изменениями

1. **Проверь текущую ветку:** Целевая интеграционная ветка - `integration/tauri-v2`. Не переключайся на другие ветки (`main`, `satichik-dev`, `experimental`) и не делай merge без прямого запроса пользователя.
2. **Прочитай документацию:** [`README.md`](README.md), [`docs/INDEX.md`](docs/INDEX.md), [`docs/AI_GUIDE.md`](docs/AI_GUIDE.md) и относящиеся к задаче спецификацию, документацию и тесты.
3. **Сначала объясни план:** Покажи, как работает существующий путь выполнения, затем предложи минимальный план. Не переписывай незнакомую подсистему до полного прослеживания её вызывающего кода, тестов и зависимостей.
4. **Хирургическая точность:** Изменяй только то, что относится к задаче. Не совмещай несвязанные исправления и рефакторинг.

## Архитектурные ограничения

- **UI и бэкенд:** Основной графический интерфейс - Tauri v2 + React (`ui/`). Связь с бэкендом идет через REST API и WebSockets шлюз (`services/gateway_service.py`). Старый интерфейс PySide6 архивирован в `ui_archive/` и по умолчанию не запускается.
- **Файловая безопасность:** Файловые операции должны идти строго через существующую песочницу `security/sandbox.py` и проверки разрешений `PermissionManager`.
- **Без произвольного шелла:** Не добавляй произвольное исполнение shell/CMD/PowerShell для действий ассистента и не обходи текущие разрешения.
- **Шина событий:** Используй существующий `EventBus` (`core/events.py`) для предусмотренного межкомпонентного взаимодействия.
- **Стабильность стека:** Не меняй основной стек, подсистемы или их жизненный цикл без конкретной причины и проверки регрессий.

## Система логирования: не переделывать без причины

Текущая модель с отдельными журналами (`core/logging_config.py`), общей сводкой ошибок `errors.log`, очисткой старых `*.log*` при запуске и сохранением логов сессии является осознанным решением. Возвращаться к вопросу только при явном запросе пользователя или при конкретной воспроизводимой проблеме.

## Известные правила подсистем

- **Steam и Протоколы:** Управление сценариями идет через `ProtocolsManager` (`core/protocols_manager.py`), `StarkProtocols` (`services/stark_protocols.py`) и `SteamManager` (`core/steam_manager.py`).
- **Синтез речи (TTS) и STT:** Распознавание голоса (Vosk + faster-whisper) и синтез (Piper TTS) локальные, их потоки и кэши не трогать без необходимости.
- **Ollama:** Сервис управляется через `core/ollama_manager.py`. По умолчанию предзагрузка модели отключена (`autoload_model: false`), модель грузится лениво при первом запросе.

## Завершение работы

После изменения обязательно проверь относящиеся к задаче тесты (`pytest tests/`), обработай ошибки, просмотри `git diff` и обнови документацию, если изменилось поведение.
