# JARVIS — локальный настольный ассистент (Kirieshka v2)

JARVIS — настольный ассистент для Windows 11. Он объединяет локальную языковую модель через Ollama, текстовый чат, инструменты для работы с файлами, мультимедиа и приложениями, динамическую телеметрию системы, голосовой ввод, локальный синтез речи и систему обновления через GitHub Releases.

**Текущая версия в исходниках:** `0.1.8`  
**Основной стек:** Tauri v2 (Rust + React/Vite), Python 3.12, FastAPI Gateway (REST + WebSockets), Ollama, faster-whisper, Vosk, Piper TTS.  
**Хранилище исходников:** [jelr1k/mama_kirilla_](https://github.com/jelr1k/mama_kirilla_) (активная ветка: `integration/tauri-v2`).

## Что уже реализовано

### Чат и языковая модель

- Потоковая генерация ответов через локальную модель Ollama.
- Переключатель режима размышления для отдельного запроса.
- `Command Router`: простые однозначные команды (запуск приложений, громкость, плеер, телеметрия, файлы, управление окном) обрабатываются мгновенно без обращения к LLM.
- `Tool Calling` для сложных и составных запросов: модель может последовательно вызывать разрешённые инструменты и получать результаты их выполнения. Ограничение — до пяти раундов вызова инструментов на одну генерацию.
- Для каждого запроса формируется ограниченный набор доступных инструментов, а `ToolExecutor` повторно проверяет разрешения перед выполнением.
- История текущего диалога, обработка подтверждений и потоковый вывод ответа.
- Статистика последней генерации: токены, длительность, скорость, время до первого токена и параметры размышления.

### Файлы и Workspace

Файловые инструменты работают с реальными объектами рабочего каталога `workspace/`. Доступны:

- поиск и чтение файлов;
- создание файлов и папок;
- запись и перезапись содержимого;
- удаление, переименование, копирование и перемещение файлов (с защитой от случайной перезаписи `overwrite=False`);
- получение подробной информации об объекте.

Вкладка **Workspace** позволяет просматривать рабочие файлы, добавлять файл через диалог выбора или перетаскиванием из Проводника, а также редактировать алиасы.

`WorkspaceIndex` индексирует реальное содержимое рабочего каталога. Поиск поддерживает нормализацию имён, автоматические и пользовательские алиасы со стеммингом (`AliasManager`), нечёткое сопоставление (`_FUZZY_FILENAME_THRESHOLD = 0.72`) и интерактивную обработку неоднозначных совпадений.

### Управление звуком и мультимедиа

- Локальное управление системным звуком Windows через Windows CoreAudio API / pycaw:
  - изменение громкости (сделай громче/тише, прибавь на N%);
  - отключение (Mute), включение (Unmute) и переключение звука с раздельным отслеживанием состояния;
- Управление медиаплеером:
  - отправка системных команд паузы, воспроизведения, пропуска (следующий трек) и возврата (предыдущий трек).
- Команды обрабатываются Command Router напрямую без обращения к LLM.

### Системная телеметрия и мониторинг железа

- Динамический сбор метрик системы без жесткого зашивания конкретных моделей оборудования:
  - процент загрузки процессора (CPU) и статистика по ядрам;
  - распределение оперативной памяти (RAM);
  - свободное и общее место на дисках;
  - опрос состояния видеокарты (GPU) и видеопамяти (VRAM) с поддержкой NVIDIA NVML, AMD, WMI и DXGI;
  - время непрерывной работы системы (Uptime).
- Живые бейджи CPU и RAM в шапке главного окна с автообновлением.

### Безопасность инструментов

- Файловые пути проверяются через отдельную песочницу (`sandbox`); путь, который разрешается за пределами `workspace/`, блокируется.
- Не используются произвольные команды CMD, PowerShell или shell как универсальный способ выполнения действий.
- Разрешения инструментов можно включать и отключать во вкладке **Инструменты**.
- Запись, перезапись, удаление, переименование, копирование и перемещение файлов требуют подтверждения пользователя.
- Запуск приложений отделён от файловых операций. В настройках есть отдельный переключатель, разрешающий открытие приложений за пределами Workspace.

Эти ограничения относятся к встроенным инструментам JARVIS. Они не заменяют общую безопасность Windows и не означают, что все возможные действия с компьютером доступны ассистенту.

### Управление приложениями

JARVIS умеет искать установленные приложения, проверять состояние процессов, запускать приложения и поддерживаемые объекты Workspace, сворачивать и безопасно закрывать приложения (с подтверждением пользователя), а также открывать HTTP/HTTPS-ссылки. Запуск использует системные механизмы Windows и не строится на выполнении произвольных shell-команд.

### Голосовой ввод и wake word

- Локальное распознавание речи через `faster-whisper`.
- Обнаружение ключевой фразы через Vosk; по умолчанию используется `Jarvis`. Wake word можно отключить и изменить в настройках.
- Запись с выбранного микрофона и автоматическое завершение записи после обнаружения тишины.
- Ленивая загрузка модели Whisper при первом распознавании.
- Нормализация частых голосовых вариантов пунктуации и расширений файлов (`voice.command_normalizer`).
- Распознанный текст поступает в тот же путь обработки сообщений, что и текстовый ввод: Command Router → при необходимости LLM и разрешённые инструменты.
- В настройках доступны модель Whisper (`small`, `medium`, `large-v3` или локальная модель), число CPU-потоков, beam size, VAD, таймкоды, использование предыдущего текста, микрофон и порог тишины.
- Статистика распознавания показывает время подготовки аудио, загрузки модели и транскрибации, параметры запуска и real-time factor.

### Синтез речи (TTS)

- Локальная генерация речи через Piper TTS. Текст не отправляется в облачный сервис озвучивания.
- Отдельная очередь и рабочий поток: синтез и воспроизведение не блокируют интерфейс.
- Один канал озвучивания для готовых ответов ассистента и шуточных реплик RoflService; промежуточные токены и сообщения о ходе фоновой работы не читаются вслух.
- В настройках можно отключить автоматическую озвучку, выбрать один из поддерживаемых русских голосов, настроить скорость/громкость, скачать модель и проверить тестовую фразу.
- Модель голоса скачивается по запросу пользователя один раз и хранится отдельно в пользовательском каталоге. Автоматическая озвучка по умолчанию отключена.
- Wake word временно игнорирует входящий звук во время воспроизведения, чтобы динамик не запускал ассистента сам на себя.

Подробное описание компонентов, событий и потока запросов: [архитектура](docs/ARCHITECTURE.md).

### Графический интерфейс Kirieshka v2

- Модульный пакет кинематических анимаций `ui/animations/`:
  - `AnimatedTabBar` и `AnimatedTabWidget` (`SlidingStackedWidget`) со скольжением вкладок и централизованным сбросом состояния анимаций;
  - `ButtonHoverFilter` для тактильного отклика и плавного свечения кнопок;
  - `AnimatedToggle` — неоновые свитчи вместо стандартных чекбоксов;
  - Плавный скролл чата (`SmoothScroller`), пульсация записи и индикатор размышлений;
  - Анимированная заставка запуска (`SplashScreen`) в стиле современных игровых сервисов со статусами готовности.
- Тёмная неоновая кибер-тема (`ui/theme.py`) с цветовой палитрой deep slate, neon cyan и emerald green.
- Индикаторы ресурсов CPU и RAM в шапке окна.
- Вкладки основного окна: **Чат**, **Генерация**, **Настройки**, **Алиасы**, **Workspace**, **Инструменты**, **Ollama**, а также служебное окно справочника команд.

### Настройки и рофлы

- Имя ассистента, используемая модель Ollama, температура, размер контекста и максимум токенов ответа.
- Настройки локального голосового распознавания и выбора микрофона.
- Адрес Ollama Server и тестовый режим только с Command Router, без LLM.
- Вероятностные шуточные реакции на действия (в том числе управление звуком и телеметрию), включая отдельные «демонические» реплики (`services/rofl_service.py`).

## Проверка и установка обновлений

В приложении есть система обновления через **GitHub Releases**:

- проверка обновлений вручную из настроек и фоновая периодическая проверка;
- сравнение версии приложения с опубликованными релизами;
- подтверждение пользователя перед скачиванием;
- загрузка ZIP-архива, проверка архива и его безопасных путей;
- создание резервной копии текущей установки;
- запуск отдельного процесса обновления, чтобы не заменять файлы работающего приложения;
- установка обновления и повторный запуск JARVIS;
- попытка отката к резервной копии, если установка завершается ошибкой.

При обновлении предусмотрено сохранение пользовательских настроек, Workspace, журналов и кэшей моделей Ollama/Hugging Face. Журнал процесса обновления пишется в `logs/updater.log`.

## Где хранятся данные

Расположение приложения определяется автоматически, а не привязано к фиксированному пути:

- `workspace/` — рабочие файлы, доступные встроенным файловым инструментам.
- `logs/` — журналы диагностики.
- `%APPDATA%\\Jarvis\\settings.json` — пользовательские настройки.
- `%APPDATA%\\Jarvis\\aliases.json` — пользовательские алиасы.

### Журналирование

Журналы разделены по подсистемам: общие сообщения, ошибки, запуск, фатальные ошибки, события, голосовой ввод, команды и инструменты, Ollama/LLM, загрузка зависимостей и updater. При обычном запуске через bootstrap прежние файлы `*.log*` в каталоге `logs/` очищаются намеренно, после чего журналы создаются заново.

## Запуск из исходников

Требуется Windows 11, Python 3.11+ (рекомендуется Python 3.12) и установленная отдельно Ollama.

Из корня репозитория в CMD:

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r config\requirements.txt
python start\bootstrap.py
```

Для обычного запуска можно использовать `start.bat`: он быстро проверяет зависимости через `start/check_dependencies.py` без повторного вызова pip и запускает bootstrap.

## Запуск тестов

Из активированного виртуального окружения в корне проекта:

```bat
python -m pytest -q
```

В проекте реализовано более 490 тестов, покрывающих песочницу, файловые операции, Command Router, голосовые подсистемы, воспроизведение TTS, анимации UI и процесс обновления.

## Структура проекта

- `core/` — жизненный цикл приложения, конфигурация, пути, события, шина `EventBus`, задачи и управление Ollama.
- `llm/` — интерфейс провайдера, запросы к Ollama, потоковые ответы и статистика.
- `chat/` — сообщения и история диалога.
- `services/` — чат, Command Router, RoflService, статистика и сервисы обновления.
- `tools/` — реестр инструментов, файловые операции, управление процессами, медиаплеер (`media_control.py`) и системная телеметрия (`system_info.py`).
- `security/` — разрешения, валидация аргументов и файловая песочница `sandbox.py`.
- `voice/` — захват микрофона, faster-whisper, Vosk wake word, нормализация команд и локальный синтез речи Piper TTS (`voice/tts/`).
- `presentation/` — 11 контроллеров, связывающих backend и UI через EventBus.
- `ui/` — страницы, диалоги, темная кибер-тема и модульный пакет анимаций `ui/animations/`.
- `start/` — bootstrap, точка входа, быстрая проверка зависимостей и процесс обновления.
- `config/` — список зависимостей и конфигурационные шаблоны.
- `tests/` — тестовый набор pytest.
- `docs/` — техническое задание, сквозной индекс кодовой базы, архитектура и справочник команд.

## Что пока не реализовано

- Полноценная проверенная автономная сборка и установщик `.exe`.
- Real-time/streaming TTS (воспроизведение речи частями до завершения полной генерации ответа LLM).
- Автоматический выбор LLM-модели по сложности задачи (Model Router).
- Выполнение произвольных команд CMD/PowerShell как отдельный контролируемый инструмент (сейчас прямой shell-доступ заблокирован ради безопасности).
