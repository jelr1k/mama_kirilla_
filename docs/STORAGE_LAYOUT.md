# Структура хранения данных и файлов JARVIS (Kirieshka v2)

Этот документ описывает актуальную файловую раскладку приложения: где сохраняются пользовательские конфигурации, локальные логи сессий, кэш нейромоделей, сессионные токены безопасности и временные данные.

Центральный модуль управления путями в кодовой базе: [`core/app_paths.py`](../core/app_paths.py).

---

## 1. Сводная таблица путей

| Тип данных | Системный путь по умолчанию | Переменная / fallback | Назначение |
|---|---|---|---|
| **Пользовательские настройки** | `%APPDATA%\Jarvis\` | `C:\Users\<User>\AppData\Roaming\Jarvis` | Постоянные настройки, профили, сценарии протоколов, алиасы |
| **Логи работы** | `%LOCALAPPDATA%\Jarvis\logs\` | `C:\Users\<User>\AppData\Local\Jarvis\logs` | Журналы подсистем текущей и прошлых сессий |
| **Кэш нейросетевых моделей** | `%LOCALAPPDATA%\Jarvis\models\` | `C:\Users\<User>\AppData\Local\Jarvis\models` | Локальные веса Piper TTS (ONNX), Vosk, faster-whisper |
| **Токен безопасности шлюза** | `%LOCALAPPDATA%\Jarvis\session.token` | `C:\Users\<User>\AppData\Local\Jarvis\session.token` | Одноразовый криптографический токен сессии REST / WebSocket |
| **Рабочая песочница (Sandbox)** | `<APP_ROOT>\workspace\` | Внутри папки проекта / установки | Изолированная директория для создания и обработки файлов ассистентом |
| **Окружение Python (dev)** | `<APP_ROOT>\.venv\` | Внутри папки проекта | Изолированное виртуальное окружение зависимостей бэкенда |
| **Сборка фронтенда (dev)** | `<APP_ROOT>\ui\src-tauri\target\` | Внутри каталога `ui/` | Скомпилированные Rust-бинарники Tauri v2 и промежуточные артефакты |

## 2. Пользовательские конфигурации (`%APPDATA%\Jarvis`)

Каталог предназначен для данных, которые сохраняются при обновлениях приложения и могут синхронизироваться между сессиями пользователя:

* **`settings.json`**  
  Основной конфигурационный файл. При первом запуске автоматически формируется слиянием эталонного шаблона [`config/settings.json`](../config/settings.json) и пользовательских параметров. Содержит:
  - Имя ассистента и триггерную фразу голосовой активации (wake word).
  - Настройки аудио: выбранный индекс микрофона, громкость TTS, модель синтезатора речи.
  - Настройки LLM: имя модели Ollama, температура, системный промпт.
  - Настройки Telegram-бота (токен и whitelist идентификаторов пользователей).
  - Системные горячие клавиши и параметры автозапуска.

* **`protocols.json`**  
  Пользовательские макросы и сценарии «Протоколы Старка» (последовательности запуска приложений, веб-страниц, аудиодорожек и системных действий).

* **`websites.json`**  
  Сопоставление голосовых триггеров и URL-адресов веб-ресурсов (например, «ютуб» → `https://youtube.com`).

* **`aliases.json`**  
  Пользовательские псевдонимы для быстрого запуска установленных программ и утилит.

## 3. Локальные данные и журналы (`%LOCALAPPDATA%\Jarvis`)

Каталог предназначен для файлов, привязанных к конкретной машине и текущей сессии:

### 3.1. Логирование (`logs/`)
Система логирования автоматически распределяет события по специализированным файлам для удобной отладки:
* **`jarvis.log`** — основной журнал жизненного цикла приложения.
* **`errors.log`** — единая сводка всех ошибок уровня `ERROR` и `CRITICAL` со стектрейсами.
* **`voice.log`** — события подсистем распознавания речи (Vosk, Whisper).
* **`tts.log`** — события локального синтеза и воспроизведения речи (Piper TTS).
* **`ollama.log`** — запросы к локальной языковой модели, параметры стриминга и ответы.
* **`commands.log`** — распознанные намерения пользователя и результаты маршрутизации команд.
* **`dependencies.log`** — проверка и установка зависимостей.
* **`update.log`** — работа подсистемы проверки, скачивания и установки обновлений.
* **`startup.log`** / **`fatal.log`** — журнал раннего bootstrap-запуска и дампы `faulthandler`.
* **`events.log`** — межкомпонентные сообщения системной шины `EventBus` в JSON-формате.

> **Политика очистки:** При каждом новом запуске бэкенда через `start/bootstrap.py` старые файлы `*.log*` в каталоге `logs/` очищаются, чтобы каждая сессия начиналась с чистых диагностических журналов.

### 3.2. Кэш моделей (`models/`)
Тяжелые бинарные файлы нейромоделей не хранятся в репозитории Git и не засоряют исходный код:
* Файлы голосов Piper TTS (`*.onnx` и сопутствующие `*.onnx.json`).
* Распакованные акустические модели Vosk.
* Кэш весов модели распознавания faster-whisper.

### 3.3. Токен сессии (`session.token`)
* При старте бэкенда (`start/main.py`) генерируется случайный криптографический токен (64 символа hex) и записывается в `%LOCALAPPDATA%\Jarvis\session.token` с правами доступа текущего пользователя.
* Rust-слой оболочки Tauri v2 считывает этот токен через защищённую нативную IPC-команду `get_session_token` и передаёт его фронтенду.
* Все REST API запросы и WebSocket соединение к шлюзу `127.0.0.1:8765` валидируют данный токен в заголовке `X-Session-Token` и параметре `?token=`, предотвращая доступ сторонних процессов в системе к управлению компьютером через ассистента.
* При штатном завершении работы бэкенда токен автоматически удаляется.

## 4. Рабочая песочница (`workspace/`)

Каталог `<APP_ROOT>\workspace\` служит изолированной областью для операций файловой системы:
* Все скрипты автоматизации и файловые действия ассистента выполняются через песочницу [`security/sandbox.py`](../security/sandbox.py) и менеджер разрешений `PermissionManager`.
* Доступ за пределы `workspace` и разрешенных пользовательских папок (Документы, Загрузки) требует явного подтверждения либо блокируется политикой безопасности.

---

## 5. Портативный режим (Portable Fallback)

В случае, если приложение запускается в изолированном окружении, где переменные среды Windows `%APPDATA%` или `%LOCALAPPDATA%` не определены:
* `core/app_paths.py` автоматически переключает хранение на относительные каталоги:
  - Настройки: `<APP_ROOT>\user_data\`
  - Логи и кэш: `<APP_ROOT>\local_data\`
* Приложение продолжает работать в штатном режиме без вылетов и сбоев доступа.
