# GEMINI.md — Контекст и архитектурный гайд для LLM (Kirieshka v2 / mama_kirilla_)

Выжимка архитектуры, актуального стека и правил для LLM при работе с репозиторием `jelr1k/mama_kirilla_` (ветки `experimental`, `osnova`).

Подробное руководство см. в [`AI_GUIDE.md`](AI_GUIDE.md) и [`ARCHITECTURE.md`](ARCHITECTURE.md).

---

## 1. Стек и технологии

* **Платформа:** Windows 11, Python 3.11/3.12
* **GUI:** PySide6 (Qt) + модульный пакет кинематических анимаций `ui/animations/`
* **События:** `EventBus` (`core/event_bus.py`) и 11 контроллеров слоя `presentation/`
* **LLM:** Локальный сервер Ollama (легкие модели Qwen/Gemma)
* **STT:** `faster-whisper` (модель `small` на CPU, `int8`, язык `ru`)
* **Wake Word:** `vosk` (детекция ключевой фразы)
* **TTS:** `Piper TTS` (локальный синтез через ONNX в `voice/tts/`)
* **Тесты:** `pytest` (500+ тестов)

---

## 2. Архитектурный поток (Data Flow)

```text
[Пользователь (UI чат / Голосовой ввод)]
                   ↓
       services/command_router.py
          /                 \
(Четкий паттерн / алиас)   (Сложный / разговорный запрос)
         ↓                                 ↓
  Прямой Tool (без LLM)           Ollama Manager (LLM)
         ↓                                 ↓
   Мгновенный ответ                 Tool Calling
                                          ↓
                                     ToolExecutor
                                          ↓
                                     EventBus / UI
```

**Критический принцип:** `CommandRouter` обязан отсекать простые команды (запуск/закрытие софта, управление медиа и звуком, телеметрия ПК, системные папки, скриншоты, файлы) и выполнять их напрямую через `tools/` без обращения к LLM.

---

## 3. Правила разработки для моделей

1. **Хирургическая точность:** менять только относящиеся к задаче строки, без попутного переформатирования и удаления чужих комментариев.
2. **Простота кода:** не создавать абстракций «на будущее». 50 читаемых строк всегда лучше 200 строк с переусложнёнными фабриками.
3. **Безопасность:** файловые операции изолированы в `workspace/` через `security/sandbox.py`.
4. **Портативность:** все пути строятся через `core/app_paths.py`, никаких `C:\...`.
5. **Проверка перед коммитом:** обязательный прогон тестов `python -m pytest -q`.
