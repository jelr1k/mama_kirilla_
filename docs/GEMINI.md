# GEMINI.md — Контекст и правила разработки Jarvis для LLM

Краткая выжимка архитектуры, стека и жестких правил для LLM/агентов при работе с репозиторием `localjarvisgolos` (ветка `osnova`).

---

## 1. О проекте и стек

**Jarvis / Kirieshka v2** — модульный локальный голосовой и текстовый ассистент под Windows 11 с акцентом на приватность, быстродействие и локальную работу без облаков.

- **Язык и среда:** Python 3.11+, Windows 11
- **GUI:** PySide6 (Qt)
- **Шина событий:** Кастомный `EventBus` (слабая связность модулей)
- **LLM бэкенд:** Локальная Ollama (легкие модели под Tool Calling)
- **STT (распознавание):** faster-whisper
- **Wake-word:** Vosk (детекция активационной фразы)
- **TTS (синтез речи):** Piper TTS (локальные ONNX-голоса)
- **Тесты:** pytest

---

## 2. Архитектурный поток (Data Flow)

```text
[Пользователь (UI чат / Голос)]
              ↓
    services/command_router.py
         /                 \
(Четкий паттерн / алиас)   (Сложный / разговорный запрос)
       ↓                                 ↓
 Прямой Tool (без LLM)           Ollama Manager (LLM)
       ↓                                 ↓
  Мгновенный ответ                 Tool Calling
                                         ↓
                                    ToolExecutor
                                         ↓
                                    EventBus / UI
```

**Критический принцип:** Command Router обязан отсекать простые команды (запуск приложений, медиа, громкость, выключение, открытие файлов, алиасы) и выполнять их напрямую через `tools/`. Запрос отправляется в LLM только тогда, когда это свободный диалог, формулировка неоднозначна или требуется рассуждение/композиция тулов.

## 3. Структура проекта

- `core/` — фундамент: `config_manager.py`, `ollama_manager.py`, `alias_manager.py`, `event_bus.py`, `tool_executor.py`.
- `services/` — бизнес-логика: `command_router.py`, `chat_service.py`, `rofl_service.py` и др.
- `tools/` — исполняемые инструменты: `applications.py`, `media_control.py`, `system_info.py`, `filesystem.py`, реестр `registry.py`.
- `ui/` — компоненты PySide6:
  - `main_window.py` — главное окно с бейджами CPU/RAM и переключением вкладок.
  - Страницы: `chat_page.py`, `settings_page.py`, `statistics_page.py`, `workspace_tab.py`, `alias_page.py`, `tools_page.py`, `ollama_page.py`.
  - Пакет `ui/animations/` — модульная система кинематических анимаций.
  - `theme.py` — киберпанк темная тема (deep slate, neon cyan, emerald green).
- `voice/` — голосовой пайплайн: `microphone.py`, `speech_recognizer.py`, `wake_word.py`, подсистема `voice/tts/` (Piper).
- `config/` — конфигурационные файлы JSON, алиасы, схемы настроек.
- `docs/` — документация: `00_INDEX.md` (путеводитель), `INDEX.md` (трассировка код-тесты), `01_REQUIREMENTS/`, `02_ARCHITECTURE/`.
- `tests/` — тестовый набор `pytest`.

## 4. Графика и анимации (`ui/animations/`)

Все анимации интерфейса изолированы в отдельном пакете `ui/animations/`:

- `tab_animations.py` — `AnimatedTabBar` (подсветка hover glow при наведении на вкладку и скользящая неоновая полоса активной вкладки) и `AnimatedTabWidget` (скольжение страниц с кроссфейдом).
- `button_animations.py` — `ButtonHoverFilter` (плавное неоновое свечение рамки/фона при наведении и тактильный прожим клика) и `install_button_micro_interactions`.
- `toggle.py` — `AnimatedToggle` (неоновый свитч с плавно скользящим круглым бегунком взамен стандартных чекбоксов).
- `effects.py` — `PulsingEffect` (циклическая пульсация записи/распознавания), `SmoothScroller` (плавный скролл чата), `ThinkingIndicator` (полоса раздумий LLM), `animate_cards_entrance` (каскадное появление блоков), `fade_in_window`.
- `splash_screen.py` — `SplashScreen` (заставка Kirieshka v2 в стиле Discord с прогресс-баром при старте приложения).

## 5. Жесткие правила для ИИ

1. **Иерархия истины:**
   - Фактический код ветки `osnova` > Тесты (`pytest`) > Документация в `docs/` > Предположения.
   - Если код расходится с документацией — сначала выясняем поведение кода, а не слепо верим тексту.

2. **GUI и асинхронность:**
   - Никогда не блокировать главный поток Qt (UI). Любые тяжелые вызовы (Ollama, Piper TTS, Whisper, файловые операции) выполняются в отдельных воркерах (`QThread` / `threading`), результат возвращается через сигналы Qt или `EventBus`.

3. **Портативность путей:**
   - Никаких захардкоженных путей к дискам (`C:\...`, `D:\...`).
   - Использовать `app_paths.py` и относительные пути от корня проекта.

4. **Система логирования:**
   - Не ломать существующую структуру логов. Ошибки обязаны попадать в специализированные логгеры и `logs/errors.log`.

5. **Безопасность и валидация:**
   - Все пути к файлам и запуск процессов проверять через правила безопасности и валидаторы проекта.

6. **Тестирование перед сдачей:**
   - Любое изменение в коде валидировать прогоном тестов (`pytest tests/`). Если затронут Command Router или Tools — запуск соответствующих тест-сьютов обязателен.
