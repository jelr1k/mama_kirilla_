# Технический аудит кодовой базы Jarvis (Kirieshka v2)
**Дата:** Ноябрь 2026 г.  
**Целевая ветка:** `osnova`  
**Объем проверки:** Бэкенд (Python), тесты (pytest, 657 тестов), фронтенд (Tauri v2 + React), конфигурации и файловая структура.

---

## 1. Резюме аудита

Кодовая база прошла масштабную миграцию на Tauri v2 + React, но сохранила исторический "балласт":
- Несколько файлов являются 100% мертвым грузом (мусорный XML-дамп, заброшенный моковый React-компонент, мертвый модуль `chat/history.py`, неиспользуемые методы).
- Слой `presentation/` (13 контроллеров) де-факто остался артефактом старого PySide6 UI: в рабочем headless-режиме Tauri используется только `tray_icon.py`, а остальные контроллеры живут ради совместимости и старых тестов.
- Обнаружен опасный дубликат системной логики: две разные реализации функции `close_application` в `tools/applications.py` и `tools/application_closer.py`, вызываемые разными сервисами.
- В проекте сформировались 5 явных "God Object / God Module" монолитов (`gateway_service.py`, `command_router.py`, `telegram_bot.py`, `vpn_manager.py`, `Settings.jsx`), которые сильно усложняют поддержку.

**Критичность изменений:** Низкая. Удаление этих методов безопасно, но требует быстрой сверки с публичными сигнатурами.

### 2.3. Рудимент: Слой `presentation/` и PySide6 контроллеры

- **Суть проблемы:** В проекте есть 14 файлов в `presentation/` (около 1500 строк кода): `alias_controller.py`, `chat_controller.py`, `dependency_controller.py`, `ollama_controller.py`, `protocols_controller.py`, `settings_controller.py`, `statistics_controller.py`, `tools_controller.py`, `voice_controller.py`, `wake_word_controller.py`, `websites_controller.py`, `workspace_controller.py`, `application_controller.py`.
- **Реальное состояние:** Основной графический интерфейс работает на Tauri v2 + React. Бэкенд запускается через `start.bat` -> `bootstrap.py --headless` -> `start/main.py`. В headless-режиме из всей папки `presentation` создается **только** `tray_icon.py`!
- Все остальные 13 контроллеров инициализируются **только** в ветке `else` в `start/main.py`, где создается окно старого PySide6 интерфейса из архива `ui_archive/`.
- При этом для контроллеров написаны тесты (например `tests/unit/test_settings_controller.py` на 378 строк).
- **Критичность и риски рефакторинга:**
  - *Риск:* **Средний/Высокий**. Если просто вырезать `presentation/`, отвалятся тесты контроллеров и запуск с ключом `--legacy-gui`.
  - *Рекомендация:* Вынести оставшиеся контроллеры в `ui_archive/presentation/`, либо явно пометить как легаси-адаптеры, а `tray_icon.py` перенести в `services/` или `core/`.

## 3. Дублирование кода и скрытые конфликты

### Две разные функции `close_application`
В проекте сосуществуют две реализации закрытия приложений:
1. `tools/applications.py:562` -> `close_application(name: str)`: ищет процесс через `psutil` и принудительно завершает дерево процессов.
2. `tools/application_closer.py:37` -> `close_application(name: str)`: обертка над тем же `ApplicationResolver`, но использующая WScript.Shell через PowerShell для закрытия ярлыков Windows.

**В чем коллизия:**
- В реестре тулов `tools/registry.py` зарегистрирована версия из `application_closer.py`.
- А сервис сценариев `services/stark_protocols.py` импортирует `close_application` напрямую из `tools.applications`!
- В тестах одна часть проверяет `test_applications.py`, а другая - `test_application_closer.py`.

**Критичность изменений:** **Высокая**. Нужно объединить реализацию в одном месте (`tools/application_closer.py` сделать единой точкой входа), иначе поведение протоколов и LLM-инструментов расходится. Риск регрессии средний: потребуется поправить импорт в `stark_protocols.py` и прогнать тесты.

## 4. Объекты на декомпозицию (God Objects & God Modules)

Ниже приведен список самых перегруженных узлов системы, отсортированный по степени критичности.

### 4.1. `services/gateway_service.py` (1508 строк, 56 REST-эндпоинтов + WebSocket)
- **Что внутри:**
  - Класс `WebSocketHub`: менеджмент соединений, heartbeat, отправка очередей сообщений.
  - Огромный монолит `GatewayService._setup_routes()`: 56 эндпоинтов на все темы (чат, статус, телеметрия, настройки, автозапуск, обновление ПО, управление Ollama, протоколы, воркспейс, алиасы, Steam, VPN, приложения, микрофоны, синтез речи).
  - Мост EventBus -> WebSocket: трансляция всех событий ядра в сокеты клиента.
- **Почему это плохо:** Любая правка в API настроек или VPN заставляет трогать полуторатысячестрочный файл сетевого шлюза. Сложно читать, тестировать и поддерживать.
- **План декомпозиции:**
  1. Вынести `WebSocketHub` в отдельный модуль `services/gateway/hub.py`.
  2. Использовать `fastapi.APIRouter` и разбить эндпоинты по доменам:
     - `services/gateway/routers/chat.py`
     - `services/gateway/routers/settings.py`
     - `services/gateway/routers/system.py` (telemetry, autostart, shutdown, updates)
     - `services/gateway/routers/voice.py` (microphones, tts, assets)
     - `services/gateway/routers/integrations.py` (steam, vpn, protocols, apps)
  3. В `gateway_service.py` оставить только конфигурирование сервера, подключение роутеров и запуск uvicorn.
- **Оценка рисков:** **Высокий риск**. Это главный шлюз общения бэкенда с Tauri. При рефакторинге легко сломать пути эндпоинтов или сериализацию моделей. Делать только при наличии зеленых тестов `test_gateway_service.py`.

### 4.2. `services/command_router.py` (1213 строк)
- **Что внутри:**
  - Строки 32-450 (более 400 строк!): захардкоженный словарь `ROUTER_COMMANDS` с огромным набором regex, описаний и шаблонов команд.
  - Строки 675-934 (260 строк!): метод `_route_extended_tools` со сплошным каскадом `if/elif` по разбору команд (медиа, громкость, запуск приложений, сайты, протоколы, файлы, системные действия).
- **Почему это плохо:** Смешаны данные конфигурации команд, регулярные выражения, диспетчеризация и бизнес-логика исполнения.
- **План декомпозиции:**
  1. Вынести каталог команд и регулярки в `config/commands_catalog.json` или `services/command_catalog.py`.
  2. Разделить метод `_route_extended_tools` на стратегии/хэндлеры по категориям (`MediaCommandHandler`, `AppCommandHandler`, `FileCommandHandler`).
- **Оценка рисков:** **Высокий риск**. На роутер завязано поведение голосовых команд и быстрых текстовых запросов без участия LLM. В проекте 11 файлов тестов на регулярки роутера.

### 4.3. `modules/telegram_bot.py` (1004 строки)
- **Что внутри:**
  - Реализация кастомного HTTP клиента Telegram (через httpx).
  - Цикл polling обновлений с обработкой сетевых сбоев.
  - Генерация inline-клавиатур (главное меню, VPN, выключение, отмена).
  - Обработчики команд `/status`, `/screen`, `/vpn`, `/ping`, `/sleep`, `/shutdown`, `/reboot`, `/lock` и передача свободного текста в нейросеть.
- **План декомпозиции:**
  - Разбить на пакет `modules/telegram/`:
    - `client.py` (HTTP-запросы к Bot API, отправка сообщений и фото)
    - `keyboards.py` (разметка кнопок)
    - `handlers.py` (обработка команд бота и коллбэков)
    - `bot.py` (жизненный цикл сервиса и поллинг)
- **Оценка рисков:** **Средний риск**. Модуль изолирован, тесты проверяют базовые сценарии через моки httpx.

### 4.4. `core/vpn_manager.py` (980 строк)
- **Что внутри:**
  - Конфигурации и сигнатуры VPN клиентов (Flclash, Hiddify, V2RayN, Zapret).
  - Глубокое сканирование файловой системы и реестра Windows для поиска установленных программ и zip-архивов.
  - Распаковка и запуск служб Zapret.
  - Модуль автоматизации GUI через UIAutomation (`pywinauto` / UIA): поиск окон клиентов, поиск кнопок по ключевым словам и клики по ним без участия пользователя (`_activate_with_uia`).
- **План декомпозиции:**
  - Вынести UIA-автоматизацию в `core/vpn/uia_controller.py`.
  - Вынести логику распаковки и управления Zapret в `core/vpn/zapret_manager.py`.
  - Вынести поиск клиентов по реестру и дискам в `core/vpn/discovery.py`.
- **Оценка рисков:** **Средний риск**. Код UIA хрупок к изменениям версий Windows и сторонних VPN-клиентов. Изоляция UIA сделает ядро чище и стабильнее.

### 4.5. `services/rofl_service.py` (856 строк)
- **Что внутри:** Около 600 строк файла занимают статические списки шуточных реплик Jarvis (`ROUTER_LINES = {...}`). Самой логики там менее 250 строк.
- **План декомпозиции:** Вынести словарь реплик в отдельный файл данных `services/rofl_phrases.py` или `config/rofl_phrases.json`.
- **Оценка рисков:** **Минимальный (Безопасно)**. Простая механическая правка без изменения логики.

### 4.6. Фронтенд: `ui/src/components/Settings.jsx` (1497 строк, 63 КБ)
- **Что внутри:** Гигантский монолитный компонент настроек. В одном файле смешаны: общие настройки ассистента, селекторы микрофонов, загрузка/удаление моделей Whisper, TTS-голоса с предпрослушкой, настройки обновлений, бэкапы, токен Telegram бота, проверка сети и сброс настроек.
- **План декомпозиции:** Разбить на дочерние компоненты по вкладкам:
  - `components/settings/AssistantSettings.jsx`
  - `components/settings/VoiceSettings.jsx` (STT Whisper + TTS Piper)
  - `components/settings/TelegramSettings.jsx`
  - `components/settings/UpdatesSettings.jsx`
  - `components/settings/NetworkSettings.jsx`
- **Оценка рисков:** **Средний риск**. В `Settings.jsx` очень много перекрестных `useState`. При декомпозиции важно аккуратно передать общие пропсы или вынести состояние в единый хук.
