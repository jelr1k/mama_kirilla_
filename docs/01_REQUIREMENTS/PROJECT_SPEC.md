# Jarvis — актуальное техническое задание

**Версия документа:** 3.1  
**Дата обновления:** 2026-10-22  
**Проект:** локальный голосовой/текстовый ассистент Jarvis для Windows 11  
**Стек:** Python, PySide6, Ollama, локальные LLM, faster-whisper, Vosk, Piper TTS  
**Репозиторий:** `jelr1k/mama_kirilla_`  
**Основная ветка текущей разработки:** `osnova`

> Это главный документ требований проекта. Фактическое состояние кода подтверждается отдельно документом `docs/04_STATUS/IMPLEMENTATION_STATUS.md`. Будущие функции и идеи вынесены в `docs/01_REQUIREMENTS/ROADMAP.md`.

## 0. Текущее состояние

### 0.1. Архитектура — ГОТОВО

Реализованы:

- автоматическое определение корня Jarvis;
- рабочий `Workspace` относительно расположения приложения;
- пользовательские настройки и алиасы;
- автоматические базовые алиасы для добавляемых файлов;
- sandbox и безопасная работа с путями;
- файловые инструменты с защитой от перезаписи;
- инструменты управления приложениями и Windows-ярлыками;
- безопасное закрытие приложений с обязательным подтверждением;
- Command Router;
- ограниченный tool scope для конкретного запроса;
- многораундовый Tool Calling;
- управление Ollama Server и моделью из UI;
- расширенное логирование;
- тесты ключевых компонентов.

### 0.2. Command Router — ГОТОВО

```text
Пользовательский ввод
        ↓
Command Router
        ├─ простая однозначная команда → прямой инструмент
        └─ сложная/составная задача → LLM + разрешённые tools
```

Обычный разговор не должен получать полный набор системных и файловых инструментов.

### 0.3. Tool Calling — ГОТОВО

`GenerationWorker` поддерживает до 5 последовательных раундов Tool Calling. После каждого вызова результат возвращается модели для продолжения задачи или формирования финального ответа.

### 0.4. Файловая подсистема — ГОТОВО

Поиск, чтение, создание, удаление, копирование и перемещение файлов реализованы внутри разрешённого `Workspace`. Все файловые команды используют единый resolver (`tools.paths.resolve_workspace_path`) и живой `WorkspaceIndex` как источник истины. Голосовые команды нормализуются (`voice.command_normalizer`), поддерживается контролируемое fuzzy-сопоставление (`_FUZZY_FILENAME_THRESHOLD = 0.72`) с сохранением списка совпадений при неоднозначности. Операции копирования и перемещения защищены от случайной перезаписи.

### 0.5. Голосовой ввод и вывод — ГОТОВО

- **STT:** Локальный STT реализован через `faster-whisper`.
  - Модель `small` (или настраиваемая из UI);
  - `device="cpu"`, `compute_type="int8"`, язык `ru`;
  - целевая частота 16 kHz, `beam_size=5`, `vad_filter=True`;
  - ленивая загрузка модели при первом запросе;
  - нормализация распознанных голосовых команд и расширений (`voice.command_normalizer`).
- **Wake Word:** Локальное фоновое распознавание ключевой фразы через Vosk с автоматическим подавлением на время воспроизведения речи.
- **TTS:** Локальный синтез речи через Piper (ONNX на CPU) в отдельном фоновом потоке `jarvis-tts-worker` с поддержкой подготовленных ассетов и LRU-кэша.


### 0.6. Требование к STT и именам файлов

Ошибки распознавания являются ожидаемой особенностью STT и не должны ломать файловую систему.

Например:

```text
«тест точка txt»
        ↓
STT может получить разные варианты текста
        ↓
resolver проверяет реальные объекты Workspace
        ↓
test.txt найден, если он реально существует
```

Нельзя объявлять `test.exe` существующим только потому, что Whisper так распознал слово. Нельзя выдавать вымышленные кандидаты.

### 0.7. Добавление файлов в Workspace через UI — ГОТОВО

Вкладка «Workspace» является основной точкой добавления объектов. Пользователь может:

- нажать «Добавить файл» и выбрать файл через QFileDialog;
- перетащить файл из Проводника в область Workspace.

После добавления:

- файл копируется в Workspace без создания дубликата при повторном добавлении того же объекта;
- WorkspaceIndex сразу видит реальный объект;
- автоматически создаются только отсутствующие безопасные алиасы;
- существующие пользовательские алиасы не перезаписываются;
- повторная индексация не плодит дубликаты алиасов;
- файл сразу появляется в списке вкладки «Workspace».

Все операции копирования проходят через существующий sandbox-путь Workspace.

### 0.8. Автоматические алиасы — ЧАСТИЧНО ГОТОВО

При добавлении файла через UI Jarvis автоматически создаёт базовые алиасы без обращения к LLM.

Для `Steam.url` создаются, например:

```text
Steam
Steam.url
```

Для известных приложений поддерживаются устойчивые русские варианты, например:

```text
Steam → стим
Discord → дискорд
Telegram → телеграм
Minecraft → майнкрафт
Geometry Dash → геометрия дэш
```

Для неизвестных английских названий автоматический перевод намеренно не выполняется, чтобы не получать случайные и бессмысленные переводы. Пользовательские алиасы по-прежнему можно добавить вручную.

Следующее улучшение: распространить автоматическую индексацию алиасов на все способы появления объектов в `Workspace`, а также отдельно хранить автоматически созданные и пользовательские алиасы, чтобы переиндексация не затрагивала ручные настройки.

## 1. Завершённые и текущие задачи

### 1.1. Разрешение имён файлов и голосовая нормализация — ГОТОВО

Реализовано:
- единый поиск файлов для открытия, чтения и других команд через `TargetResolver` и `tools.paths.resolve_workspace_path`;
- фактическое содержимое `WorkspaceIndex` как единый источник истины;
- нормализация имён файлов, расширений и знаков препинания после STT в `voice.command_normalizer`;
- контролируемое сопоставление (`_FUZZY_FILENAME_THRESHOLD = 0.72`) с реальными объектами;
- сохранение списка совпадений и интерактивный выбор номера при нескольких кандидатах без вымышленных объектов;
- защита от перезаписи файлов при перемещении и копировании.

### 1.2. Добавление файлов через UI — ГОТОВО

Сценарий добавления перенесён во вкладку «Workspace». Alias Manager больше не является обязательным этапом добавления объекта.

### 1.3. Автоматические алиасы — ЧАСТИЧНО ГОТОВО

Автоматические алиасы теперь регистрируются при обновлении Workspace по фактическому содержимому Workspace. Повторная регистрация идемпотентна и не перезаписывает пользовательские алиасы или конфликтующие алиасы других объектов.

Alias Manager остаётся редактором имён, а не обязательным способом добавления объекта в Workspace.

## 2. Планы на будущее

### 2.1. Model Router — ПЛАН НА БУДУЩЕЕ

Отдельный слой автоматического выбора модели по типу и сложности задачи пока не реализован и не относится к текущему этапу разработки.

В будущем Model Router должен автоматически выбирать подходящую локальную модель с учётом типа задачи, требуемого качества, доступных ресурсов и характеристик компьютера.

### 2.2. Другие перспективные направления

К дальнейшему развитию относятся функции, которые не являются частью ближайшего этапа стабилизации:

- долгосрочная память;
- модульная архитектура специализированных функций;

- дополнительные голосовые возможности;
- расширенное управление процессами;
- дополнительные способы автоматизации.

## 3. Сетевая особенность голосовой подсистемы

В пользовательском окружении локальный Happ может предоставлять прокси `127.0.0.1:10808`. Python/Hugging Face иногда получает этот адрес как SOCKS4-прокси и выдаёт `Unknown scheme for proxy URL`.

Это относится к сетевому окружению, а не к модели Whisper. При необходимости запуск Jarvis должен иметь возможность работать без наследования внешнего proxy для прямых сетевых операций.

## 4. Критерии готовности голосового ввода

Голосовой ввод считается полностью готовым для файловых команд, когда:

- Whisper стабильно преобразует аудио в текст;
- ошибки STT не приводят к ложному существованию файлов;
- реальный `test.txt` находится одинаково при открытии и чтении;
- поиск кандидатов идёт только по фактическому `Workspace`;
- неоднозначность разрешается через выбор пользователя;
- распознанный текст проходит через существующий Command Router;
- обычный разговор не вызывает файловые tools без соответствующего намерения.
